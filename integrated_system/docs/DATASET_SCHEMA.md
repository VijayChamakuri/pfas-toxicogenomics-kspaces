# Dataset schema and compatibility record

## Experimental unit represented by the files

The reusable inputs are ten edgeR contrast tables, one PFAS exposure versus its matched control. Each file contains one row per measured WormBase gene identifier. The tables are contrast-level differential-expression results, not sample-level count matrices. They therefore support cross-contrast descriptive and exploratory analyses, but they do not support refitting the original sample-level model or estimating new biological replicate variance.

## Canonical columns

| Field | Meaning | Validation |
| --- | --- | --- |
| `WB_id` | WormBase gene identifier | Non-null, unique within each contrast, identical universe across contrasts |
| `logFC` | Estimated log2 fold change for exposure versus control | Finite continuous effect used for response-pattern analysis |
| `logCPM` | Average log counts per million reported by edgeR | Finite numeric diagnostic |
| `F` | edgeR test statistic | Finite numeric diagnostic |
| `PValue` | Nominal differential-expression p-value | Required in `[0, 1]` |
| `FDR` | Within-contrast adjusted p-value | Required in `[0, 1]` |

Nine source files store the identifier in an unnamed first column and one stores `WB_id`. The validated loader normalizes only that label. It does not alter values.

## Supported compatibility decisions

- DEG counts and threshold-sensitivity summaries are supported for all ten contrasts.
- Module discovery uses the continuous logFC response matrix after an explicitly recorded gene-selection rule.
- GO enrichment requires a gene universe eligible for the selected analysis and mappable within the tested ontology namespace.
- A request for raw counts, sample covariates, replicate-level uncertainty, dose response, time series, causality, or an unmeasured chemical must abstain because those inputs are absent.
- A named gene, pathway, column, file, or tool must resolve against an authoritative local catalog before execution.

## Decision record

The DGE tables are the source of truth for this repository. Exploratory R scratch files and historical notebook outputs are audit inputs only. Scientific results must be regenerated by the maintained builders and validated loaders.
